Project Organisation

Creating Reproducible Projects


For your mini-project, and in general, you will create a reproducible project. This means you share your data, code, materials, and report.

Making Good Reproducible Projects


To make a good reproducible project, you need to make it:

  • Easy to understand
  • Easy to share and backup
  • Easy to modify or extend
  • Easily work on different computers/platforms

Don’t Make Problems for Future You


Organise everything from the start and work under the assumption that you will need to revisit or share this information in the future.

Creating a Project in RStudio


RStudio Projects (.Rproj) create a self-contained sandbox for your work. Each project maintains its own isolated working directory, history, and workspace.


Open RStudio and we will create a project.

File > New Project

Organising Files and Folders


Every file has a location, called a path, and an extension that denotes the file type.


Mac: ‘/Users/sabrinaburr/Desktop/my_data.csv’

PC: ‘C:\Users\sabrinaburr\Desktop\my_data.csv’

Naming Files


When naming files:

  • Make sure the name contains information on the content
  • Use naming conventions that make sense in alphabetical order
  • Avoid spaces, special characters, and capital letters
  • If using numbers, pad them (e.g., participant_00001.csv)
  • Use ISO 8601 standard for dates (YYYY-MM-DD)


For more naming advice, read Jenny Bryan on Naming Things

RStudio Working Directory


The working directory is where RStudio first looks for files and where it saves output.


If you’re working outside of a project, you can set your working directory manually:

Session > Set Working Directory >


You can also set the working directory using the command setwd('path/to/your/directory')

Calling Files in RStudio


When you call files in an RStudio project, you don’t need to provide the full path, provided the files are stored in the project directory (i.e., the folder).


Bad for reproducibility:

ggsave('Users/sabrinaburr/Desktop/Projects/MyProject1/Figures/graph1.png)


Better for reproducibility:

ggsave('Figures/graph1.png)


It’s best to write R code assuming the script is run from the same folder it is saved in.

Calling Files in RStudio - Here Package


Sometimes, even with organised files, you might run into issues, such as trying to run a script on Mac vs Windows.


library(here) can help with this:


ggplot(here("Figures", "graph1.png"))

Control Structures


One of the most useful early programming skills to learn is the use of loops and logical flows:

  • The if, else if, and else structures
  • The vectorised ifelse() and case_when() functions
  • The while and for loops

Fundamental Methods: If Statements


if statements say if a condition is met, do something.


# creating an object called 'a'
a <- 6


if (a > 5) {
  print("Variable is greater than 5!")
}
[1] "Variable is greater than 5!"

Control Structures: If, Else If, Else


You can build a number of conditions by using: if, else if (which acts like “or”), and else.

# rewriting so object 'a' is 0.1
a <- 0.1


if (a > 5) {
  print("Variable is greater than 5!")
} else if (a == 5) {
  print("Variable is 5")
} else {
  print("Variable is less than 5")
}
[1] "Variable is less than 5"
Conditions should be in parentheses. Curly brackets begin and end the if-statement code blocks.

Vectorised Conditions on Basic Vectors


if statements only check one value at a time. Last week we learned about vectors (lists of values). To check a whole vector at once, we use the vectorised ifelse()


# a vector of participant ages
ages <- c(22, 15, 19, 12)

# check all values at once
ifelse(ages >= 18, "Adult", "Minor")
[1] "Adult" "Minor" "Adult" "Minor"

Vectorised Conditions: Multiple Outcomes


To check multiple conditions cleanly without nested brackets, we use case_when() directly on our vectors


ages <- c(22, 35, 15, 65)

# Create three age groups cleanly
case_when(
  ages < 18 ~ "Child",
  ages >= 18 & ages < 60 ~ "Adult",
  ages >= 60 ~ "Senior",
  TRUE ~ "Unknown" 
)
[1] "Adult"  "Adult"  "Child"  "Senior"

Loops: The Concept


As long as a condition is met, do something!

We focus on two main types of loops:

  • while: Repeat an action while a condition remains true.
  • for: Repeat an action for a predefined set of values.

While Loops


While a logical condition is met, repeat the operation


a <- 0 # assigning object 'a' a value of zero 

while (a < 10) { # while a is less than 10
  print(a)       # print the current value of a
  a <- a + 2     # then add 2 to a to progress the loop
}
[1] 0
[1] 2
[1] 4
[1] 6
[1] 8

While Loops Can Be Dangerous!


A while loop evaluates a conditional check every loop. If you do not update your checked variable within the loop, it will run forever!


a <- 0 

while (a < 10) { 
  print(a) 
  # Missing: a <- a + 2
}

For Loops


Loops that iterate over an explicit, predefined set of values


my_numbers <- c(1:5) # vector of numbers 1 to 5

for (i in my_numbers) { # for every number in my_numbers
  print(i + 5)         # print that number + 5
}
[1] 6
[1] 7
[1] 8
[1] 9
[1] 10

Custom Functions


Functions are reusable blocks of code that contain three components:

  1. Take an ‘argument’ (the inputs / ingredients)
  2. Do something to those arguments inside {}
  3. Return a value (the output)

Writing Your First Function

# This function takes a numeric vector as input
square_and_mean <- function(x) {
  squared_values <- x^2                   # Square all values in the vector
  mean_of_squared <- mean(squared_values) # Calculate average of those squared values
  return(mean_of_squared)                 # Return the result
}

# Example usage:
my_vector <- c(1, 2, 3, 4, 5)
result <- square_and_mean(my_vector)

print(result)
[1] 11

Let’s check the math: \[\frac{(1^2 + 2^2 + 3^2 + 4^2 + 5^2)}{5} \rightarrow \frac{(1 + 4 + 9 + 16 + 25)}{5} \rightarrow \frac{55}{5} \rightarrow 11\]

Functions with Multiple Arguments


Functions in R are incredibly flexible. They can take multiple inputs, call other functions inside themselves, and output multiple objects as structured lists

# A function that calculates square means and then sums a second vector
multiple_op_function <- function(x, y) { 
  x_squared_mean <- square_and_mean(x) # call our previously defined function!
  
  y_sum <- sum(y)  # perform a separate operation on our second argument
  
  return(list(     # return both distinct results together as a list
    x_result = x_squared_mean,
    y_result = y_sum
  ))
}

Running Multiple Argument Functions

# Example vectors
my_vector_a <- c(1, 2, 3)
my_vector_b <- c(10, 20, 30)

# Run our function
multiple_results <- multiple_op_function(my_vector_a, my_vector_b) 

print(multiple_results)
$x_result
[1] 4.666667

$y_result
[1] 60

Let’s check the math:

x: \(\frac{(1^2 + 2^2 + 3^2)}{3} \rightarrow \frac{(1 + 4 + 9)}{3} \rightarrow \frac{14}{3} \rightarrow 4.666667\)

y: \((10 + 20 + 30) \rightarrow 60\)

Data Frames

What is a Data Frame?


In R, a data frame is the standard representation of a data table.

  • Think of it like an Excel spreadsheet.
  • It is a collection of variables (columns) that are all the same length.
  • Crucially: Each column in a data frame is just a vector!

Creating a Data Frame


Let’s build a small data frame by grouping vectors together using data.frame()

# Create separate vectors of equal length
names <- c("Alice", "Bob", "Charlie", "Diana")
ages <- c(22, 15, 35, 65)
scores <- c(88, 92, 79, 95)

# Combine them into a data frame
df <- data.frame(names, ages, scores)

print(df)
    names ages scores
1   Alice   22     88
2     Bob   15     92
3 Charlie   35     79
4   Diana   65     95

Columns are Vectors


Because columns are vectors, we can extract them using the $ operator and run calculations directly on them

# Extract the 'ages' column
df$ages
[1] 22 15 35 65
# Find the mean age
mean(df$ages)
[1] 34.25

Modifying Columns with Tidyverse


In the tidyverse, we use the mutate() verb and the pipe operator %>% (which means “and then”) to modify data frames.

If we want to add or change columns, we apply our vectorised conditional functions (ifelse() and case_when()) inside mutate().

Using ifelse() inside mutate()


Let’s add an age_status column to our df data frame based on whether participants are adults


df <- df %>% 
  mutate(age_status = ifelse(ages >= 18, "adult", "minor"))

print(df)
    names ages scores age_status
1   Alice   22     88      adult
2     Bob   15     92      minor
3 Charlie   35     79      adult
4   Diana   65     95      adult

Using case_when() inside mutate()


What if we want to create multiple groups? We can use case_when() directly inside mutate() to evaluate the ages column

df <- df %>% 
  mutate(age_group = case_when(
    ages < 18 ~ "child",
    ages >= 18 & ages < 60 ~ "adult",
    ages >= 60 ~ "senior"
  ))

print(df)
    names ages scores age_status age_group
1   Alice   22     88      adult     adult
2     Bob   15     92      minor     child
3 Charlie   35     79      adult     adult
4   Diana   65     95      adult    senior

Fundamental Principles of Good Code

Readability


Readability is how easy your code is to navigate, read, and understand. This is essential when collaborating with colleagues, but it is also an invaluable gift to your future self when revisiting old scripts!

Unreadable Code Example

Can you tell what this code is doing at a glance? What is missing?

pf <- function(n){p=1;if(n>1){i=2;while((i<(n/2+1))&(p==1)){if(n%%i==0)p=0;i=i+1}}else{p=0};return(p)}
Dense, single-line code blocks are prone to hidden errors and are nearly impossible to debug easily.

Refactoring for Readability: Spaces & Tabs


By adding vertical spacing and consistent indentation, the logical blocks immediately stand out

pf <- function(n) {
  p = 1
  if (n > 1){ 
    i = 2 
      while( (i < (n/2+1)) & (p == 1) ) {
        if (n%%i == 0) {
          p = 0
        }
        i = i + 1
      }
  } else {
    p = 0
  }
  return(p)
}

Hint: Can reformat in the menu via Code > Reformat Selection

Refactoring: Meaningful Variable Names


Let’s rename the abstract arguments (pf, n, p) into descriptive variable names

primecheck <- function(num){
  isprime = TRUE
  if (num > 1){ 
    i = 2 
      while( (i < (num/2+1)) & (isprime == TRUE) ) {
        if (num %% i == 0) {
          isprime = FALSE
        }
        i = i + 1
      }
  } else {
    isprime = FALSE
  }
  return(isprime)
}

Refactoring: Adding Clear Comments


Adding comment lines completes the code, making its design intentions clear

primecheck <- function(num){  # Check if a number is prime (assumes integer input)
  isprime = TRUE              # Flag: start by assuming our number IS prime 
  
  if (num > 1){               # Only check numbers greater than 1
    i = 2                     # Set our divisor starting point
    
    # Check potential divisors until done or we find a divisor
    while( (i < (num/2+1)) & (isprime == TRUE) ) {
      if (num %% i == 0) {
        isprime = FALSE       # Remainder is 0, so number is not prime
      }
      i = i + 1               # Increment divisor
    }
  } else {
    isprime = FALSE           # If number is <= 1, it cannot be prime
  }
  return(isprime)
}

Comments

Writing Good Comments

Comments (lines beginning with #) are ignored by R but are important for humans reading your code

  • Even experienced coders cannot understand a complex script instantly without documentation.
  • Use comments to explain why you wrote a step, not just what the step does.
  • You can write comments first to map out your coding logic before writing any actual R statements

Functionalise


Let’s compare repetitive, manual vector updating against a unified function call

# Repetitive manual operations
mynumbers = c(2, 3, 4)
mynumbers[1] <- mynumbers[1] * 2 + 1 # manually calling first element
mynumbers[2] <- mynumbers[2] * 2 + 1 # manually calling second element
mynumbers[3] <- mynumbers[3] * 2 + 1 # manually calling third element
print(mynumbers)
[1] 5 7 9

Functionalise: The Better Way


Writing a quick helper function cleans up your main code path

# Define helper function that takes parameter/argument 'num'
dub_one <- function(num) {
  return(num * 2 + 1)
}

mynumbers = c(2, 3, 4)
# Run function on vector in a single step
mynumbers <- dub_one(mynumbers) 

print(mynumbers)
[1] 5 7 9

Finding Help

Finding Help: Coding is Searching


Number One Tip: Coding is Search-Driven

Getting stuck is a normal, healthy part of learning. Figuring out how to locate your solutions is a fundamental skill.

As you build up your experience, you will learn how to search for programming assistance more effectively.

Helpful Resources: Stack Overflow

Googling Tips


  • Copy and Paste the Error: Search the error text inside quotation marks.
  • Be Explicit: Include package contexts in search queries (e.g., R ggplot2 add title to plot).

Generative AI as a Collaborative Tool

Best Ways to Utilise GenAI

Think of your AI helper as a Pair Programmer:

  • Explanation: Paste complex code or error logs and ask: “Explain this to me in plain language.”
  • Optimisation: Paste working code and ask: “How can I improve the readability or efficiency of this snippet?”
  • Rubber Ducking: Describe your logical steps to help identify blind spots before writing syntax.

Debugging: Finding Your Errors

Strategic Debugging


  • Run Line-by-Line: Do not execute large script blocks all at once. Run lines sequentially, checking your variable values after each run.
  • Read Error Messages: Take time to read error codes before searching. Identifying the general name of your bug (e.g., “subscript out of bounds”) helps you solve it.
  • Logical Errors: If code runs but produces incorrect outputs, write down your assumptions: What did you expect? What did it actually do? What must be true for this line to succeed?
