From Local Project to Public Portfolio


We’ve discussed how to use Git and GitHub to manage and version R code and how to write a reproducible analysis using Quarto.


Now, we’ll put these skills together to move beyond our local computer and publish our work to a public-facing website.

The Publishing Tool: GitHub Pages


GitHub Pages is a free, simple hosting service provided by GitHub. It takes the files in a GitHub repository and publishes them as a website.


It’s the perfect way to share analyses, project reports, or even an entire portfolio with the world, directly from our code’s repository.

GitHub Essentials for Publishing


The README.md

  • The first page visitors see on GitHub.
  • Acts as a project summary.
  • Good README = title, description, how to run, link to website.

The .gitignore File

  • Tells Git which files to ignore (e.g., .Rhistory, large datasets).
  • Keeps your repository clean.

Branches

  • Publishing usually uses main.
  • Advanced: publish from a separate gh-pages branch.

Publishing a Single Document


Step 1: Render Your Quarto File

  • In RStudio, open the .qmd file.
  • Click the “Render” button. Quarto will run the code and generate an output file, like analysis.html.

Step 2: Commit and Push

  • Stage both .qmd and .html in the Git pane.
  • Commit with a clear message.
  • Push to GitHub.

Configuring GitHub Pages


Step 3: Configure GitHub Pages

  1. Go to the GitHub repository in a browser.
  2. Click Settings → Pages.
  3. Under Build and deployment, choose Deploy from a branch.
  4. Select main and folder / (root).
  5. Click Save.

Publishing a Quarto Website


What if we want to publish multiple analyses together with a navigation bar? That’s where a Quarto Website comes in.

Step 1: Create a Quarto Website Project

  • In RStudio: File → New Project...
  • Choose New Directory → Quarto Website.
  • Includes multiple .qmd files and _quarto.yml.

The _quarto.yml File


The output-dir Option

  • Add output-dir: docs to _quarto.yml.
  • Ensures all rendered files go into docs/.
project:
  type: website
  output-dir: docs

website:
  title: "My Research Portfolio"
  navbar:
    left:
      - href: index.qmd
        text: Home

Website Publishing Workflow


Step 2: Render the Website

  • Click Render Website in RStudio.
  • Quarto builds site into docs/.

Step 3: Commit and Push

  • Stage and commit the new docs/ folder.
  • Push to GitHub.

Step 4: Configure GitHub Pages

  • Go to Settings → Pages.
  • Source: Deploy from a branch, branch main, folder /docs.
  • Save.

Extra Features: Navigation


Add pages to your site

website:
  title: "My Research Portfolio"
  navbar:
    left:
      - href: index.qmd
        text: Home
      - href: about.qmd
        text: About Me
      - href: projects.qmd
        text: Projects

Exercise: Add a new page (e.g., about.qmd) and update your navbar.

Extra Features: Themes


Quarto supports multiple built-in themes: cosmo, flatly, darkly, etc.

format:
  html:
    theme: flatly

You can also override with custom CSS for finer control.

CSS Customisation


Add a styles.css file to your project, then link it in _quarto.yml:

format:
  html:
    theme: flatly
    css: styles.css

Example styles.css:

h1 {
  color: #0066cc;
}
p {
  font-size: 1.1em;
}

Exercise: Try changing your site’s font or heading colour.

Troubleshooting GitHub Pages


Common Issues

  • Website doesn’t appear → Did you push the docs/ folder?
  • Wrong branch → Ensure Pages is set to main.
  • Looks out of date → Clear browser cache or force re-render.

Fix Strategy

  1. Check your _quarto.yml for output-dir.
  2. Confirm docs/ exists and is on GitHub.
  3. Revisit Settings → Pages to confirm branch/folder.

Extensions: Publishing Slides


Quarto can publish presentations as well:

format:
  revealjs:
    theme: simple
    transition: slide
  • Slides are rendered to HTML just like reports.
  • Push them to GitHub and they can be shared via Pages.

Extensions: GitHub Actions


Instead of pushing rendered docs/, you can let GitHub do the rendering:

  • Enable GitHub Actions with a Quarto workflow.

  • GitHub will build the site every time you push.

  • Cleaner workflow but slightly more setup.

Useful for: larger sites, frequent updates.

Live Demonstration: A Full Quarto & GitHub Workflow


Let’s put it all together:


  1. Create a new Quarto Website project and initialise Git.
  2. Configure _quarto.yml to output to docs/.
  3. Render the project and inspect the docs/ folder.
  4. Commit and push to a new GitHub repository.
  5. Configure GitHub Pages to publish from docs/.
