The Problem: Data Analysis Chaos


Imagine you’re working on a research project. Your folders look something like this:

  • my_analysis.R
  • my_analysis_final.R
  • my_analysis_final_version2.R
  • my_analysis_final_comments.R
  • my_analysis_final_REALLY_final.R


…and your collaborator just messaged to say they’ve made changes and accidentally deleted a key section.

The Problem: Data Analysis Chaos


This is a version control nightmare!

The Solution: Version Control


Version control is a system that records changes to a file or set of files over time so that you can recall specific versions later. It’s like a “time machine” for your code and documents.


Git is the most widely used modern version control system in the world.

  • It’s a powerful tool that runs on your local computer
  • It tracks every change, who made it, and why
  • It allows you to easily revert to old versions, explore different ideas (branches), and merge changes

Git vs. GitHub: What’s the Difference?


Git

  • What it is: The software that tracks changes
  • Where it lives: On your local computer
  • Think of it as: The engine of a car


GitHub

  • What it is: A web-based hosting service for Git repositories
  • Where it lives: In the cloud
  • Think of it as: The parking garage for your car️

Why use Git and GitHub for Research?


For Individual Work

  • Reproducibility: You have a documented history of every step of your analysis.
  • Backups: Your code is safely stored in the cloud. If your hard drive fails, your work is safe.
  • Experimentation: Easily create separate “branches” to test new ideas without breaking your main project.

For Collaborative Work

  • Seamless Collaboration: Multiple people can work on the same project simultaneously without overwriting each other’s work.
  • Transparency: See who made what changes, when, and why.
  • Code Review: Use features like Pull Requests to review and discuss changes before merging them.

Core Git Concepts


1. Repository (Repo)

A project folder that Git is tracking. It contains all the project’s files and a hidden .git directory that holds the version history.

2. Commit

A “save point” in your project’s history. It’s a snapshot of the files in your repository at a specific moment in time, with an associated message explaining the changes.

3. Branch

A separate line of development. Think of it as a parallel universe for your project where you can make changes without affecting the main version. The main branch is typically called main or master.

4. Push and Pull

  • Push: Uploading your local commits to a remote repository (like GitHub).
  • Pull: Downloading commits from the remote repository to your local machine.

Branches, Merges, and Conflicts


  • Branching allows experimentation without affecting main project
  • Merging combines changes from different branches
  • Conflicts occur when two changes overlap; must be resolved manually

Installing Git and Setting Up GitHub


Step 1: Install Git

  • Download and install Git for your OS: Windows, macOS, Linux

Step 2: Create a GitHub Account

  • Go to github.com and register for a free account.

Step 3: Configure Git in RStudio

  • Tools → Global Options → Git/SVN → Set Git executable path
  • Configure user name and email

Getting Started: RStudio & Git


  • RStudio integrates with Git to simplify version control
  • Use the Git pane to stage, commit, push, and pull

Live Demonstration: Collaborative Workflow


  1. Create a repository on GitHub
  2. Clone it into RStudio
  3. Make a small change locally → commit → push
  4. Edit file directly on GitHub → pull back into RStudio

Hands-On Exercise: First Commit


  • Create a README.md file with your name and one fun fact
  • Stage, commit, and push the file to GitHub
  • Verify it appears on GitHub

Hands-On Exercise: Branching


  • Create a new branch experiment
  • Make a small change → commit → push
  • Merge back into main and resolve any conflicts

Best Practices for Research


  • Commit often with meaningful messages
  • Use branches for experimental work
  • Avoid committing large files; use .gitignore
  • Keep the main branch clean
